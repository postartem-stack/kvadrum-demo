## После покупки домена
1. Зафиксировать точное имя домена, регистратора и тип адреса (www или без www).
2. В GitHub: Settings -> Pages -> Custom domain. Настроить DNS у регистратора по официальной документации GitHub Pages для выбранного варианта.
3. Проверить верификацию домена, DNS propagation, HTTPS и включить Enforce HTTPS, когда станет доступно.
4. Проверить редиректы между www / без www, ссылку github.io и основной canonical.
5. Задать og:url, og:image и canonical с новым доменом; проверить предпросмотр ссылок.
6. Убрать noindex, nofollow **только после** согласования публичного запуска; подготовить sitemap.xml и robots.txt.
7. Подключить корпоративную почту и выбранный серверный/внешний приём заявок. Не публиковать API-ключи/SMTP пароли в GitHub или клиентском JavaScript.
8. Проверить отправку тестовой заявки end-to-end, получение письма, спам-фильтры, сообщение об ошибке и защиту от повторов.
9. Запустить Lighthouse Mobile/Desktop и GitHub Actions QA, проверить мобильное меню, CTA, контактные ссылки.
10. Финальное принятие заказчиком.

## Важные правила
- До подключения e-mail форму **не активировать**.
- Не включать индексацию демо по умолчанию.
- Не менять домен и DNS без подтверждённого адреса.
- GitHub Actions и PR использовать для каждой доработки; фиксировать результаты в Jira KAN.
